# 주간 작업 Issue와 팀 연결 보드

GitHub Issue가 작업 기록의 원본입니다. 보드는 공개 저장소의 Issue를 읽기만 하며, 첫 로드 또는 **GitHub 새로고침** 버튼으로 최신 내용을 가져옵니다. 웹훅·백그라운드 동기화·사이트에서 GitHub로 쓰기는 사용하지 않습니다.

## 작성 순서

1. [새 Issue](https://github.com/Pseudo-Lab/Science-Agent-Leaderboard/issues/new/choose)에서 담당 팀의 **주간 작업** 양식을 선택합니다. 양식은 이 변경이 기본 브랜치에 병합된 뒤 표시됩니다.
2. 주차(OT 또는 W01~W16), 질문·목표, 결과 요약, 완료 기준을 작성합니다. 담당자는 GitHub **Assignees**에서 지정합니다. 미지정 시 보드에 작성자를 표시합니다.
3. 문서·PR·공개 결과 링크는 `자료 링크`에 http(s) URL을 한 줄에 하나씩 입력합니다.
4. `선행 Issue`에는 필요한 자료를 만드는 **같은 저장소** Issue의 `#번호` 또는 전체 URL을 적습니다. 여러 개면 줄바꿈·공백·쉼표로 구분합니다. 설명은 별도 요약 항목에 적습니다.
5. `영향받는 팀`과 `전달 내용·요청할 결정`으로 누가 무엇을 결정해야 하는지 적습니다.
6. 다음 작업을 만들 때 이번 Issue를 선행 Issue로 연결합니다. 다른 주차로 이어지는 관계는 보드의 **다음 주 인계**에 나타납니다.
7. 진행 중에는 새 Issue를 반복 생성하기보다 본문의 결과·상태·링크를 수정합니다. 댓글은 토론에 사용하되, 결정 사항은 본문에 반영해주세요. 보드는 댓글을 읽지 않습니다.

## 5개 팀 양식

| 양식 | 작성할 핵심 내용 |
| --- | --- |
| Task·데이터 | 문제·데이터·요구 산출물·성공 조건의 공개 요약 |
| 연구·실험 설계 | 연구 근거·가설·비교 변수·고정 조건 |
| Agent·Harness | 구현 변경·실행 조건·코드 PR·공개 실행 요약 |
| Evaluation | 검증 결과·실패 유형·효과·비용·한계의 공개 집계 |
| Leaderboard | 저장·조회·비교 기능·필요한 데이터 형식 |

한 팀에 여러 작업을 등록할 수 있습니다. 팀을 선택한 뒤 작업 선택 목록에서 각 Issue를 확인합니다.

## 상태와 연결 규칙

- `공유 완료`인 선행 Issue만 준비된 것으로 판단합니다. 닫았다는 사실만으로 완료로 보지 않습니다.
- `not_planned`로 닫힌 Issue는 `중단`입니다. 공유 완료로 적혀 있어도 준비된 자료로 보지 않습니다.
- 찾을 수 없거나 양식이 잘못된 선행 Issue는 확인 필요·대기로 표시합니다. 다른 저장소의 Issue를 선행 자료로 연결하는 것은 지원하지 않습니다.
- **실선**은 후속 Issue가 명시한 선행 관계입니다. **점선**은 아직 구체적인 후속 Issue와 연결되지 않은 전달 예정 팀입니다.
- 연결 지도는 선택한 주차의 팀 간 관계를 묶어 보여줍니다. 같은 팀 내부 의존 관계는 상세 패널에서 확인합니다. 다른 주차 연결은 인계 탭에 표시합니다.
- 연결의 화살표는 자료 흐름을 나타냅니다. 팀 간 왕복 협업도 허용하며, 실행 가능한 DAG나 일정 계산기로 해석하지 않습니다.
- 보드는 `양식 버전 = SAL-WEEKLY-V1`인 Issue만 읽습니다. 양식 제목을 임의로 바꾸면 읽지 못할 수 있습니다. 오류는 별도 목록으로 표시합니다.

## 공개 범위

이 저장소의 기존 공개 정책을 따릅니다. 공개 가능한 작업 요약·코드·집계 링크만 작성합니다. 원시 로그, 전체 Prompt, Gold label, 내부 채점 설정, 인증정보, 개인 식별 정보는 Issue나 첨부에 넣지 않습니다. 양식과 보드 코드에는 개인의 실명이나 고정 계정 배정을 포함하지 않습니다.

## 보드 실행·운영

`tools/team-board/index.html`을 정적 웹 서버로 열거나 해당 폴더를 정적 사이트로 배포합니다. 외부 빌드 의존성은 없습니다. `board-core.js`, `app.js`, `style.css`를 같은 위치에 둡니다. 로컬 단일 HTML을 만들려면:

```sh
node tools/team-board/package-standalone.cjs /absolute/path/team-flow.html
```

GitHub 공개 REST API를 브라우저에서 직접 읽습니다. 인증 토큰은 요구하거나 저장하지 않습니다. 공개 API의 IP 기준 요청 한도와 네트워크 상태에 영향을 받습니다. 열기·수동 새로고침 때만 조회하고, 중복 동시 요청은 막습니다. 100개씩 열린/닫힌 Issue를 페이지별로 읽으며 PR은 제외합니다. 2,000개를 넘기거나 중간 페이지 조회가 실패하면 부분 결과를 완료로 표시하지 않습니다. 마지막 성공 자료가 있으면 그대로 유지하고 오류·마지막 동기화 시각을 표시합니다.

이 버전은 공개 저장소 전용입니다. 비공개 전환 시 브라우저에 토큰을 넣지 말고 인증된 서버 연동을 별도로 구현해야 합니다. GitHub Issue 변경에는 사이트 재배포가 필요 없지만 화면 코드나 파싱 규약 변경에는 재배포가 필요합니다.

## 개발 검증

```sh
node --test tools/team-board/board-core.test.cjs
node tools/team-board/generate-forms.cjs
```

양식 필드와 파서 계약은 함께 변경해야 합니다. 테스트는 다중 작업, 주차 간 연결, 잘못된 참조·양식, 닫힘/중단 처리, 링크 안전성, 페이지네이션과 부분 실패를 검증합니다.

참고: [GitHub Issue Forms](https://docs.github.com/en/communities/using-templates-to-encourage-useful-issues-and-pull-requests/syntax-for-issue-forms), [Repository Issues API](https://docs.github.com/en/rest/issues/issues#list-repository-issues).
